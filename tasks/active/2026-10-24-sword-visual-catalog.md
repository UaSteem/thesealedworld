Статус: checked-awaiting-acceptance; обычная проверка выбрана владельцем 2026-10-24. Независимая ревизия: not-requested.

«Подготовь для меча Т0–Т5 Python словарь и Pydantic модели по существующему подходу проекта. JSON оставим рабочим описанием ассетов, к генератору пока не подключаем. Но потом начнем думать над генератором».

## План

1. Сверить DTO/resource-подход Items, соглашение ADR-0001, материалы и шесть SVG.
2. Подготовить пассивные модели набора/варианта/каталога и Python-определения с индексами; предоставить явную проверку ссылок на существующий каталог Items.
3. Проверить ошибки данных, соответствие рабочего JSON и файлов; выполнить целевые тесты и линтер.
4. Завершить выбранную проверку и зафиксировать ограничения.

## Границы

Новая локальная подготовка ресурсов; существующие механические DTO, ItemCatalogService.load_default(), генератор и прочие рабочие изменения в checkout сохраняются. Условия аффиксов и алгоритм выбора пока не реализуются: у текущих шести вариантов нет ограничений по аффиксам. Тиры материалов T6–T7 не добавляются.

## Наблюдения

До реализации прочитаны Items DTO/resources/catalog service, новые проектные соглашения, ADR и рабочий манифест меча. В checkout много параллельных изменений; работать только с файлами текущей задачи.

## Результат и доказательства обычной проверки

Добавлены `dto/visuals.py` и `resources/visuals/{__init__,sword}.py` в Items. Pydantic-структура: каталог → наборы → варианты. У набора одна или несколько механических баз, у варианта ID, ID материала, тир материала, локальный source path и визуальное состояние. Дубликаты проверяются до построения трёх ID-словарей. Как в SkillCatalogService, индексы производятся через cached_property; технически это обычные dict, документирован запрет их изменения по соглашению.

Материалы, механика, редкость, текстовое обогащение и условия выбора не копируются. Политика аффиксов отложена. Один и тот же материал/тир допускает несколько художественных вариантов. Явный `validate_item_references()` получает уже существующие base_items/materials, проверяет ссылки, тир, категории и ограничения материала; ничего не загружает и не публикует.

Проверено ведущим 2026-10-24:

- `.venv/Scripts/python.exe -m pytest tests/backend/features/items/test_visual_catalog.py tests/backend/features/items/test_catalog_service.py --no-cov -q`: **59 passed in 3.85s**. Новые тесты проверяют шесть реальных SVG и их SHA из рабочего JSON, совпадение материалов/тиров, сериализацию, дубликаты, неизвестные ссылки, несогласованный тир и запреты материала, общую основу для нескольких баз, несколько вариантов одного тира, некорректные пути/поля/тиры и пустые наборы.
- Ruff check и Ruff format --check для четырёх новых Python-файлов: pass. Первоначальное замечание форматтера в тесте исправлено; форматирование не меняло поведение.
- В отдельном чистом Python-процессе обычный `ItemCatalogService.load_default()` не загружает `resources.visuals` (проверка sys.modules).
- Поиск ссылок в backend/frontend: новый DTO импортируется только новыми Python-ресурсами. Существующие runtime/generator/bootstrap/API/UI/instance/storage файлы этой задачей не менялись.
- Ссылки документации разрешаются; diff --check для затронутых tracked-файлов и проверка хвостовых пробелов новых Python-файлов: pass. Предупреждение Git о CRLF→LF для прежнего index.md не является ошибкой содержимого.
- Рабочий JSON и SVG не редактировались; чтение их тестом не делает JSON runtime-источником. Доставка ассетов во frontend не запускалась.

Документация: `docs/ru/backend/features/items/visual_catalog.md`, ссылка в index, актуализация стадии ADR-0001 и обоих asset README. Пример показывает только явную валидацию и lookup, не реализует селектор.

Ограничения: проверен подготовленный локальный каталог, не игровое отображение и не выдача предмета. Полный проектный checker не запускался; для изолированных моделей и ресурсов выполнены целевые проверки. Принятие пользователем ожидается.
