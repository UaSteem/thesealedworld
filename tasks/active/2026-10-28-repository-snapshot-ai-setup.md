Дата: 28.10.2026.

Статус: implementation-in-progress.

## Исходный запрос и уточнения

Пользователь хочет зафиксировать текущую накопленную работу коммитом и передать
скачиваемый репозиторий помощнику/художнику, которому нужны исходные файлы по
ссылкам из материалов. Ранее указал необходимость commit/push. Сначала поручил
проверить лишние корневые папки, усомнившись в необходимости лабораторий.

Затем уточнил: корневой archive/, output/ и artifacts/ — только локальные
временные материалы до альфы. Они не должны идти в Git и production. Удалять
локальные папки сейчас не поручено. Мастерская output/rift-art-lab/ — отдельный
локальный инструмент, который нельзя включать в эти коммиты.

Последнее прямое поручение: исключить мастерскую из коммитов, закрепить её
исключение в .gitignore, сделать коммит и инструкцию установки репозитория
для другого ИИ. На отдельный вопрос выбран независимый ревизор.

## Требования

- R1. Подготовить снимок накопленной рабочей разработки, сохранив текущие
  пользовательские изменения. Не переписывать прежние коммиты/историю.
- R2. Исключить output/rift-art-lab/ из нового снимка; не превращать её
  во вложенный submodule/gitlink. Явно закрепить исключение в .gitignore.
- R3. Корневые archive/, output/, artifacts/ оставить локально; не включать
  их в итоговое дерево нового коммита и Docker build context. Локальные
  оригиналы не удалять и не перемещать без отдельного поручения.
- R4. Не публиковать окружения, секреты, логи, кэши, локальные вложения,
  зависимости node_modules и переносимые бинарные сборки. Нужные исходники
  графики сохранять как исходники, не скрывать по имени папки.
- R5. Дать другому ИИ воспроизводимую инструкцию: правильная ветка, загрузка,
  зависимости, исходники/каталоги/графика, локальный запуск и границы
  установки. Не требовать production-доступ для чтения материалов.
- R6. Проверить наличие необходимых источников в итоговом Git-дереве и
  независимость установки от исключённых локальных папок.
- R7. Провести независимую ревизию точного состава снимка и инструкции,
  разобрать замечания и только затем создать коммит.
- R8. Публиковать только рабочую ветку develop, без изменения main,
  release tags или запуска production deployment. Основание push —
  исходное поручение передать скачиваемый репозиторий через commit/push.
  Перед публикацией сверить remote; не использовать force push.
- R9. Пользователь выбрал исключить game_ui_lab/ и rift_lab/ из коммита,
  сохранив нужные общие исходники отдельно. Мастера клиента сохраняются
  копиями в assets/game_client_sources/. Локальные Lab не удаляются.

## План

1. Зафиксировать исходное состояние Git и требуемые исключения.
2. Уточнить границу двух игровых Lab; проверить связанные тесты и инструменты.
3. Обновить ignore-правила и инструкцию установки, отобрать дерево снимка.
4. Сохранить необходимые общие исходники в версионируемых местах, если это
   требуется выбранной границей, с проверкой путей/контрольных сумм.
5. Проверить исключения, недостающие зависимости, ссылки инструкции и
   релевантные проверки проекта. Сохранить точные пробелы проверки.
6. Провести независимую ревизию состава и существенных итоговых утверждений.
7. Создать коммит; выполнить обычный push develop и дать ссылку загрузки
   правильной ветки. Не заявлять деплой или полную runtime-готовность.
