# Правила обходных решений в скиллах

## Требования владельца

R1. Не внедрять обход причины (костыль) молча: сначала сообщить и обсудить решение.
R2. Применить правило не только к legacy/API, но и к ассетам, UI, прототипам и переносу существующих решений.
R3. Продумать пограничные случаи и потенциальные проблемы, не превратить обычную разработку в бесконечные согласования.
R4. Не менять runtime/ассеты, не исправлять дерево в рамках этой задачи.
R5. Сохранить действующие контракты скиллов, discovery, ownership и существующие разрешения.

Режим: обычная проверка, без независимого ревизора по действующему выбору пользователя. Новые агенты не запускаются.

## План

1. Уточнить текущие правила и минимальные точки входа.
2. Расширить пользовательский глобальный code-compatibility-decision и добавить тематический reference с определением, критериями и примерами.
3. Добавить короткий trigger в verified-execution и проектные entrypoints, проектные детали оставить в своей ссылке.
4. Проверить frontmatter/ссылки/сохранность контрактов и разобрать сценарии решений статически. Это не поведенческий eval модели.

## Границы

Глобальные пользовательские скиллы редактируются через skill-creator; project-skills-maintainer применяется только к project-owned материалам. Системные/плагиновые скиллы не менять. Подготовленные версии и исходные копии: tmp/skill-workaround-update. Для записи глобальных скиллов и .agents требуется sandbox escalation; пользователь прямо поручил эти изменения.

Статус: checked-awaiting-acceptance.


## Результат и проверка

R1–R5: implementation done / verification pass ведущим. Изменены 9 файлов: 2 глобальных пользовательских entrypoints, reference и UI metadata первого скилла; 4 проектных entrypoints и существующий проектный reference. Режим совместимости и обе routes доменных skills сохранены. Runtime/ассеты/системные/плагиновые skills в этой задаче не менялись.

Проверки: quick_validate для 6 скиллов PASS; 9 файлов совпадают с подготовленными версиями; новые routing links существуют; git diff --check по project skills PASS (есть штатные предупреждения о line endings). Оригиналы и manifest с SHA256 сохранены в tmp/skill-workaround-update. Глобальные и .agents записи выполнены через разрешённую escalation с проверкой исходных хешей.

Статически разобраны пограничные случаи:

| Случай | Ожидаемое решение по правилу |
| --- | --- |
| Отдельное дерево скрывает фиксированный дефект лесного ассета | Сообщить причину и варианты, согласовать обход до внедрения |
| Деревья нужны для процедурной вариативности/окклюзии/анимации | Не объявлять костылём автоматически |
| Ошибка/отсутствие данных превращается в ноль или успех | Не маскировать, исправить источник или обсудить обход |
| Честное состояние недоступности с повтором | Обычная обработка ошибки |
| Уже разрешённый адаптер внешнего клиента | Не спрашивать повторно, сохранить контракт/проверку |
| Моковые данные прямо поручены | Допустимы с источником и полнотой; не выдавать за расчёт движка |
| Git-поставка зависит от игнорируемой локальной папки | Дефект переносимости; исправление упаковки по scope или обсуждение обхода |
| Унаследованная заплатка в touched path | Наличие в коде не является одобрением; не расширять молча |
| Обычная авторизованная правка первопричины | Выполнить без дополнительного разрешения |

Это проверка содержания правил и структуры, не поведенческий eval модели. Нет утверждения, что инструкции гарантируют отсутствие будущих ошибок. Коммит не выполнялся.
