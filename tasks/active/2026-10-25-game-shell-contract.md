# Единый контракт игровой оболочки

Дата: 2026-10-25. Основание — прямое решение владельца в текущем обсуждении.

Исходный запрос: «центральная зона ограничена общим контейнером и разделена на 2
по вертикали и правая часть на 2 по горизонтали. это надо четко зафиксировать.
потом мы работаем только с канвасом файзера. и так во всех будущих переделках».

## Зафиксированное решение

1. Общий игровой хедер — примерно 40 CSS px высотой, по ширине страницы.
   Ограничение центральной зоны не должно ограничивать хедер.
2. Под ним — общий контейнер шириной не более 1920 CSS px, по центру.
   В ограничение входят ВСЕ три части: статус, игровое поле и чат.
3. Высота контейнера — доступная высота содержимого браузера за вычетом хедера
   и футера, если он есть. Фиксированной высоты 1080 нет. Вертикального
   центрирования уменьшенного макета внутри страницы нет.
4. Контейнер разделён на две колонки: слева постоянный HTML-статус, справа
   игровая область Phaser сверху и постоянный HTML-чат снизу.
5. Футер необязателен, не выше примерно 40 px, только версия и подобная информация.
   Добавлять его сейчас лишь ради этого документа не нужно.

```text
общий хедер ~40 px, ширина страницы
        центральный контейнер max-width: 1920px
        ┌────────────────┬─────────────────────────┐
        │                │ Phaser                  │
        │ HTML-статус    │                         │
        │                ├─────────────────────────┤
        │                │ HTML-чат                │
        └────────────────┴─────────────────────────┘
необязательный общий футер до ~40 px
```

## Четыре контрольных размера

Размеры ниже — именно область содержимого браузера. На реальном мониторе
браузерные панели могут уменьшать доступную высоту; такой случай проверяется отдельно.

| Контрольный размер | Центральная зона | Размерный профиль |
| --- | --- | --- |
| 2560×1440 | максимум 1920, внешние поля по 320 px | базовый |
| 1920×1080 | доступная ширина, максимум 1920 | тот же базовый |
| 1600×900 | доступная ширина | средний |
| 1366×768 | доступная ширина | компактный |

То есть четыре проверки и примерно два перехода размеров ниже базового профиля.
На 2560 элементы не становятся крупнее лишь из-за ширины экрана. Статус, поле
и чат согласованы между собой; нельзя отдельно уменьшать только поле.

Точные ширины левой колонки, высота чата, отступы, пороги между профилями и
минимальные размеры шрифтов/кнопок пока НЕ утверждены. Их нужно измерить и
согласовать при приведении оболочки к этому контракту, а не взять произвольно.

## Границы следующих задач

- Сначала оболочка приводится к этому контракту и принимается владельцем.
- Затем бои, путешествия/рифты, инвентарь и диалоги разрабатываются внутри
  центральной области Phaser. HTML-оверлеи возможны внутри этой области.
- Обычная работа со сценой не меняет хедер, футер, статус, чат, общий контейнер
  или правила его масштабирования.
- Для изменения оболочки нужна отдельная согласованная задача с точным перечнем
  изменений. Никаких сопутствующих перестановок при правке конкретной сцены.
- Виды сверху и в перспективе имеют отдельную компоновку. Изменение одного
  не должно автоматически перестраивать другой.
- Тестовый стенд должен показывать будущую игровую оболочку, а не отдельный
  вертикально центрированный макет со служебными заголовками и лишними полями.
- Прототип — собственная проверка. Изменение существующего игрового кода и
  перенос в основную кодовую базу — независимая ревизия по решению владельца.
