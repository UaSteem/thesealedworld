# Deploy и CI/CD: замечания после сравнения с DLC Montage

Дата: 04.10.2026. Статический просмотр конфигурации, без запуска workflow и без доступа к серверу. Это список для проверки и доработки, не подтверждение состояния production.

## Сохранить сильные стороны

- Раздельные Compose-слои infra/site/game/tg-bot.
- Одноразовые migration-сервисы с зависимостью service_completed_successfully.
- Отдельные CI, сборка релизных образов после quality gate и ручной выбор слоя деплоя.
- Метки образов по версии и полному commit SHA, проверки здоровья и непривилегированные runtime-пользователи.

## Открытые замечания

- [ ] В `.github/workflows/deploy-production.yml` при деплое одного слоя меняются DOCKER_IMAGE_* всех слоёв в общей `.env`. Обновлять только выбранный слой либо хранить отдельный release manifest каждого слоя: следующий запуск соседнего слоя не должен неожиданно использовать чужую версию.
- [ ] В этом workflow не видны GitHub environment gate и concurrency. Добавить управляемую защиту production и сериализацию деплоев, чтобы параллельные запуски не перезаписывали конфигурацию.
- [ ] В этом workflow нет явного backup/restore gate перед миграциями. Проверить существующий процесс резервного копирования и добавить ссылку/проверку восстановления; отсутствие шага в workflow не доказывает отсутствие бэкапов на сервере.
- [ ] `image_ref` принимается без явной валидации допустимого формата и подставляется в shell/config. Проверять ввод; сохранять точные digest/версии всех образов релиза и источник deploy-конфигурации.
- [ ] Версии Actions и контейнеров частично указаны тегами. Для выпуска определить политику закрепления digest/SHA и обновления зависимостей; не копировать старые версии автоматически.
- [ ] Сценарий отката приложения отдельно описать от отката БД: после новых записей переключение на старую копию базы теряет данные. Определить migration compatibility и процедуру остановки записей.
