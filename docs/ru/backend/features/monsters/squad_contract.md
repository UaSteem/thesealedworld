# Заказ и сборка отряда Monsters — контракт 6

Владелец — `monsters/encounters`. Мир, рифты и PostgreSQL не подключены. Сборка не меняет характеристики и цены каталога.

## Внешний заказ

Обязательны `encounter_type`, `location_tier` (целое 0–7), `family_ids` (ровно одна семья) и целочисленный `seed`. Необязательны `difficulty` (`easy/normal/hard`, по умолчанию normal), `party_mode` (`solo/group`, solo по умолчанию), конечный неотрицательный `player_gear_score` (обязателен для относительного бюджета), полный `profile_override` либо null. Группа пока возвращает явный отказ. Теги и конкретные списки бойцов остаются вне внешнего заказа.

## Два независимых пула

`MonsterAssemblyProfileDTO` содержит `id`, `minions`, `seniors`, `roles`, `min_members`, `max_members`, `allow_repeated_members`. Старый единый `budget` и варианты точного `core` не принимаются.

- `minions` оплачивает только миньонов.
- `seniors` оплачивает ветеранов, элиту и боссов вместе.
- `roles` задаёт разрешённые ранги и их `min_count/max_count`. Отсутствующий ранг запрещён.
- Каждый бюджет содержит `mode` (`fixed` по умолчанию либо `relative_gs`), `reference_gs` (положительный, обязателен при relative_gs), `base_points` (можно 0), `gs_threshold`, `gs_step_size`, `gs_points_per_step`, `gs_bonus_max`.
- Очки не переходят между пулами. Неиспользованный остаток остаётся в своём пуле.

Тип обычной встречи разрешает только миньонов на всех сложностях. Патруль требует минимум одного ветерана и разрешает до трёх. Охрана требует минимум одну элиту; доступны ветераны и элита. Главарь требует одного босса; допускает ветеранов и элиту, максимум один босс. Обязательного минимума миньонов нет: у встроенной роли minion min_count=0. Минимум применяется только к общей численности отряда. Это тестовые настройки состава, не гарантия боевой сложности.

Пул вариантов строится лениво из готовых кандидатов. Сначала компактный расчёт определяет максимально выполнимую численность, затем перечисляются **все уникальные составы максимального размера и на одного меньше**, не ниже общего min_members. Меньшие размеры заранее не перечисляются. Повторы сохраняются как кратность одного member_id/tier; перестановки бойцов не создают новый состав. Фиксированного лимита «100 составов» нет.

Старшие перечисляются первыми с обязательными минимумами и максимумами рангов; миньоны используют отдельный бюджет и оставшиеся места. Переноса очков и скрытого минимума миньонов нет. Максимизация стоимости старших/общего расхода больше не отбрасывает допустимые варианты. Для встроенных профилей гоблинов общий размер отряда — от трёх до шести бойцов суммарно: миньоны и старшие вместе. Минимум относится ко всему отряду, не к миньонам; отдельный бюджет старших не добавляет места сверх шести. Поэтому при максимуме три остаются только тройки. Другие семьи сохраняют общий минимум два. Полный внешний override сохраняет заданный автором минимум; если он равен двум, при максимуме три доступны и двойки. Seed выбирает конкретный уникальный состав. В итоговом списке старшие выводятся перед миньонами.

Чистый сервис разделяет `cache_identity(order)`, `build_pool(order)` и `select_from_pool(order, artifact)`. Артефакт хранит готовность, кандидатов, причины отказа и компактные индексы составов. Исходный seed, GS и заказ первого клиента не сохраняются. На попадании текущий заказ и диагностика GS рассчитываются заново без повторной проверки снаряжения. Несовпадающий ключ отклоняется.

Ключ включает семью, тир, режим, сложность, тип, весь профиль, эффективные бюджеты обоих пулов и semantic revision. Seed и сырой GS исключены: одинаковые эффективные бюджеты переиспользуют один пул. Revision вычисляется один раз на процесс по исходникам/JSON содержимого src, включая предметы, навыки, характеристики и формулы; после смены кода процесс перезапускается. Отказы также хранятся без данных первого клиента. Инфраструктурный Redis-кэш находится за отдельной границей и не меняет эту чистую сборку.

## Относительный бюджет миньонов

Все встроенные minions-пулы используют `mode=relative_gs`. Их `base_points` — номинальная сумма для эталонного GS соответствующего тира. При меньшем GS пул уменьшается без нижнего порога; возможность набрать общий минимум определяет сборщик.

```text
ratio = player_gs / reference_gs
effective = floor(min(base_points * ratio, base_points + gs_bonus_max))
scaled_points = min(base_points, effective)
bonus_points = max(0, effective - base_points)
```

Дополнительная ступенчатая прибавка к этому выражению не применяется. Например, номинал 30 при эталоне 40: GS20 даёт 15, GS40 — 30, GS52 — 39 при капе +9. При GS0 пул0; если общего минимума нет — отказ. Без GS возвращается `player_gear_score_required` до поиска кандидатов, без подстановки эталона.

Эталоны Т0–Т7: **36.326 / 55.977 / 66.664 / 119.849 / 171.053 / 312.108 / 508.203 / 814.358**. Т6–Т7 — предварительные технические ориентиры, не утверждённый баланс высоких тиров. Метаданные Studio возвращают `reference_player_gs_by_tier` и `provisional_reference_tiers`.

Пул seniors сохраняет `mode=fixed` и прежнюю ступенчатую логику:

```text
steps = floor(max(0, player_gs - gs_threshold) / gs_step_size)
bonus = min(steps * gs_points_per_step, gs_bonus_max)
effective = base_points + bonus
```

Без GS fixed-профиль использует базу и нулевой бонус. Порог и шаг seniors по тирам0–7: (35,5), (55,8), (85,12), (120,15), (170,20), (230,25), (300,30), (380,40). Внешний override использует собственные настройки буквально. Старые внешние fixed-профили работают без изменений. Они полностью заменяют встроенный профиль и не сохраняются.

## Результат и диагностика

`MonsterEncounterSelectionDTO`: `selected/rejected`, preparation, selection, attempts, reasons, profile_source/id. Конфигурация и результат содержат `minions` и `seniors`: исходные настройки, `player_gs_ratio` (null в fixed), `scaled_points`, `gs_steps`, `gs_cap_reached`, `bonus_points`, `effective_points`, `spent_points`, `remaining_points`. В конфигурации расход нулевой; результат отражает реальных бойцов. Суммарный budget_base остаётся номинальной базой: при relative_gs бюджет effective может быть меньше budget_base + bonus. `scaled_points` отражает реально доступную базовую часть. Суммарные `budget_base/bonus/effective/spent/remaining` сохранены только для сводных отчётов и равны сумме двух пулов, но не разрешают перенос очков.

`core_unavailable` означает отсутствие обязательного ранга. `budget_insufficient` с путём minions или seniors показывает неоплачиваемый минимум соответствующего пула. `squad_minimum_unaffordable` — независимые пулы не позволяют набрать общий минимум при ограничениях ролей и числа бойцов. Невозможные конфигурации не подменяются ослабленной встречей. Ошибки зависимостей не маскируются под доменный отказ.

Логи requested/completed содержат заказ, seed, независимый operation ID, время, оба пула и полученный состав. [Seed и логи](seeds_and_logging.md). Подготовка только ищет готовых кандидатов; выбор собирает отряд, не создавая runtime-инстансы. Старый подбор по GS монстров не используется.
