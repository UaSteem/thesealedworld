# Workers

`archive_chat_buffers` переносит Redis Stream-сообщения в Mongo buckets и
SQL-индекс. При временной ошибке архивирования курсор остаётся перед неуспешной
записью; последующие записи этого потока ждут повторной попытки. Некорректный
JSON пропускается с диагностикой без публикации содержимого сообщения.

Идентификаторы отсутствующих сообщений выводятся из stream ID, поэтому повтор
не создаёт новую запись. Mongo append проверяет ID и порядковый номер атомарно;
возвращаемый bucket/seq ссылается на то же сообщение и после конкурентной записи.
SQL-индекс хранит ссылку на содержимое, а не заменяет Mongo-архив.
