# Общие компоненты игрового клиента

Этап 2 переноса: исходники `src/frontend/static/js/game/client/`, графика `src/frontend/static/images/game-client/`. Эти файлы не зависят от dev-сервера Lab. Генератор использует master PNG из Lab только при подготовке пакета; браузер их не запрашивает.

## Сервисы сцены

Существующая server-session область остаётся источником маршрута. Регистрация сцены в `GameClientShell.register(domain, {key, Scene, update})` разрешается при переносе соответствующего домена. Сам этап 2 не включает новые доменные сцены и не меняет server DTO/API.

В `Scene.create({services})` для нового старта и в `update(scene, serverRoot, services)` доступны `services.assets` и `services.components`. Для инструментария существует `await GameClientShell.services()`. Повторная регистрация не создаёт второй Phaser Game.

`components.createText` получает тему из HTML и отдельную raster resolution, не меняя геометрию надписи. `fitAspect` и `createImageButton` сохраняют пропорции. `attachSemanticButton` использует настоящий HTML button с focus/Enter/Space, disabled и aria-label. `rect` — физические CSS pixels относительно positioned host; `sceneRect` — backing-store scene units. При DPR2 обе системы не следует смешивать. На sleep native-контролы скрыты, на wake восстановлены, на shutdown удалены. DOM пользователя вставляется только как текст/атрибут, не HTML.

## Текстуры и время жизни

`await services.assets.acquire(group)` возвращает lease с идемпотентным `release()`. Все пользователи одной текстуры делят одну pending-загрузку и один texture key. Последний release удаляет текстуру. Перед release сцена должна уничтожить использующие её объекты либо остановиться. Если сцену только усыпляют для быстрого возврата, она удерживает lease до shutdown: нельзя освобождать её картинки при sleep и оставлять живые ссылки.

Не запускать acquire из каждого update/layout. Получать lease один раз на входе, удерживать через resize, освобождать на окончательном выходе. При устаревшем асинхронном входе сразу release полученного lease; не применять его к новой сцене. Ошибка загрузки явно выводится потребителем с повтором, не заменяется успешным пустым экраном. Неиспользуемые группы не загружаются. Локальные ключи, принадлежащие другому loader, считаются коллизией.

`inspect()` возвращает `residentBytes`, `textures`, `downloads`, `transferredBytes`, `decodeMilliseconds`. `residentBytes` — оценка width×height×4, не замер драйвера GPU. `transferredBytes` — сумма PNG bytes декодированных загрузок; это не фактические wire bytes HTTP cache. Время включает fetch+decode+создание текстуры.

Все 11 PNG вместе: 1 770 000 bytes файлов, 8 806 348 bytes RGBA (~8,40 МиБ). Два исходных листа2048² требовали32МиБ RGBA. Вырезки совпадают с master пиксель-в-пиксель; уменьшения разрешения нет. Каталог содержит исходный master hash и crop, runtime SHA256 и размеры. URL каждого PNG содержит первые12 hex SHA256. `catalog.json` и модули инвалидируются общей static version. Старые hashed файлы не удалять автоматически, пока возможны открытые сессии старой версии.

Пересборка: `.venv/Scripts/python.exe tools/game_ui_migration/build_ui_assets.py`. Источники и exact crop перечислены в генераторе; он не перерисовывает оформление. Автоматического downscale нет: inspector при DPR2 уже близок к master crop по высоте. Отдельный уменьшенный slot возможен после визуального сравнения.

## Граница адаптеров данных

Доменные adapters добавляются вместе с инвентарём, сценарием, сервисами и боем по этапам3–8. Направление: существующий typed Backend DTO → frontend presentation model → сцена; команды идут через существующие frontend routes/API clients. Не читать game DB/Redis из frontend и не вычислять игровую механику в сцене.

Отсутствующее поле не заменять нулём/тестовым значением. Недоступный модуль показывать отдельным состоянием «Сейчас недоступно»; сетевой отказ — ошибкой с повтором; пустую настоящую коллекцию — пустым состоянием. Новый контракт вынести владельцу с перечнем полей и рисками до зависимой реализации. Общие компоненты этапа2 не создают фиктивные DTO и не объявляют домен готовым.


## Сценарий — подключённый renderer

Доменscenario регистрируется лениво изclient/scenario.js. SessionContextBuilder добавляет scenario_client_payload через frontend projection; template помещает его в JSON script внутри существующегоscenario-panel-root. Source DTO и Backend не расширены. HandlercanRender оставляет прежний HTML, если проверенной проекции нет.

СценаGameClientScenario читает только публичные поля, безопасно преобразованный художественный текст, доступные Backend ответы и выбранные правые widgets. Непрозрачный extra_data/context/session metadata не публикуется. Старые formatterbr/divwhisper/spancolor превращаются в текст и переносы; inlineHTML не выполняется. Cataloglabels разрешаются существующим GameCatalogCache. Технические SCENARIO/Quest/Node/Step/phase ключи не выводятся в игровую панель.

Canvas answer вызывает реальную текущую скрытую HTML-кнопку со marker data-game-client-scenario-action. Она сохраняет действующий HTMXPOST/game/scenario/step, char_id/action_id, CSRF, ResponseDirector, OOB иHX-Redirect. На время запроса choicebridge блокирует повтор; после неопределённой сетевойошибки автоматического повтора нет, предлагается обновить существующую/game/session.

Защита позднего ответа выполняется до применения: прямой listenerhtmx:beforeOnLoad на исходной кнопке проверяет connected/originroot/domain/char. Это важно, потому что afterRequest уже поздно дляHX-Redirect/OOB. При удалении/смене корня pendingXHR также отменяется. Один afterRequest guard сам по себе недостаточен.

Вступлениеawakening_rift использует ту же presentation. Финальный enter_prepared_rift остаётся существующей Backend-границей отдельно дорабатываемого рифта; готовность нового renderer не подтверждает проход всей цепочки.


## Exploration — подключённый renderer

`client/exploration.js` лениво регистрирует `GameClientExploration`. Frontend-проекция принимает существующий `WorldNavigationDTO`, encounter и local map. Неподдерживаемый payload сохраняет прежний HTML. Город использует серверный viewport 7×7; сведения local map присоединяются по loc_id. Геометрия и рисунок клетки не предоставляют разрешение движения.

Осмотр клетки не отправляет команду. Действия используют только опубликованные move/interact/use-service tokens и прежние HTMX маршруты с точными параметрами. Контекст располагается внутри игровой области, глобальная правая панель скрыта только для этой сцены. Встреча показывает переданные варианты и сведения, без автоматически добавленной атаки или обхода.

Защита поздних ответов повторяет сценарный beforeOnLoad guard. Неопределённая ошибка запрещает повтор команды до обновления. Старый клиентский таймер перемещения сохранён как UX ограничение, не объявляется серверной проверкой. При окончательном выходе Exploration останавливается и освобождает свои текстуры; инвентарь временно усыпляет сцену. Общие Game и чат сохраняются.

Контракты Backend не расширялись. Объекты и останки остаются информационными там, где отсутствует целевое действие. Новые жилые адреса и входы не выдумываются. Интерьеры сервисов относятся к следующему этапу; отдельный рифт не затронут.


## Арена и городские помещения

`client/places.js` регистрирует один renderer `GameClientPlaces` для arena/city_services. Проекция `city_services/view_models/client.py` вызывается и из первоначального SessionContextBuilder, и из ResponseDirector для partialответов. Необработанный metadata/group_lobby/value не передаётся сцене.

Согласованные paintedWebP публикуются `tools/game_ui_migration/build_runtime_places.py` из лабораторных сжатых версий в runtimeпапку places; мастерJPEG не загружается игроку. Загружается фон текущего помещения и освобождается при уходе. Таверна и портал сохраняют действующий background_url, поскольку отдельный утверждённый интерьер отсутствует.

Hotspot открывает локальный осмотр. Реальный переход/услуга выполняются исключительно серверной кнопкой через places_transport и прежние POST маршруты. Выбор группы/турнира не активирует демонстрационную функциональность. room/rest и отдельный NPCstart_dialogue сохранены; отсутствие кнопок в массиве не означает отсутствие отдельного NPC.

Арена использует полный viewport для подтверждений, без отдельного modal=true пути. confirm появляется только из значения фактической кнопки. Поиск опрашивается check_match, подготовка боя — check_combat_ready при фактическом metadata.polling и arena_session_id. Старый автоматический HTMXpoll отключён, когда есть placesprojection, чтобы не отправлять двойные запросы. Polling приостанавливается под overlay, прекращается после выхода/ошибки, не подтверждает бой и не воспроизводит неопределённую команду повторно.

Новый Backendконтракт для переноса существующих действий не понадобился. Новые торговля/ремонт/строительство/жильё/liveboard и полноценные групповые бои этим переносом не реализованы. Старые шаблоны/transport сохранены; исходная версия доступна в stage00архиве.
