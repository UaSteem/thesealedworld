# Игровые токены и темы

Контракт реализован 2026-10-24. Он меняет оформление существующих игровых экранов, но не переносит компоновку Rift Lab или игровые экраны в Phaser.

## Исходники и сборка

- `theme_bundle.css` импортирует `game/core/scales.css` и только `game/themes/adventure.css`; результат — `theme.css`.
- `game_bundle.css` импортирует reset, компоненты, shell, игровые домены и desktop responsive. Он не импортирует палитру; результат — `game.css`.
- Загрузчики runtime и preview подключают theme до game. Оба файла собираются штатным StaticCompiler. У игрока ничего не компилируется.
- `game/themes/classic.css` — полный отключённый набор значений того же контракта. Он не входит в runtime bundle, настройки и загрузчики. Для сравнения разрешена отдельная локальная preview-сборка common scales + classic.
- `game/core/tokens.css` оставлен отдельным compatibility entry для автономной лаборатории: scales + classic. Это не runtime entry; лаборатория применяет собственные экспериментальные theme overrides. Не импортировать эту обёртку из game bundle.

## Словарь

Существующие смысловые имена `--col-*`, `--r0`…`--r7`, `--font-*`, `--text-*`, `--sp-*` сохранены. Adventure использует slate-поверхности, тёплый белый текст, золотые акценты и teal для действий. Цвета здоровья, энергии, успеха и редкости сохраняют смысл.

`scales.css` задаёт общие шкалы текста, spacing, небольших размеров, радиусов и font weights, а также aliases. Правила grid/flex, breakpoints, относительная геометрия и локальные размерные tokens остаются в game CSS. Изменение палитры не переставляет панели.

Исторические компоненты содержали сотни близких RGB-оттенков и множество вариантов прозрачности. Для их полного сохранения в Classic введены стабильные `--tone-<family>-<number>-rgb`: семейства surface, text, accent, danger, success, action, energy, magic и neutral. Classic хранит исходные RGB-каналы; Adventure связывает оттенки семейства со смысловыми `--theme-*-rgb`. Surface shades разделены на base/inset/panel/raised по исходной яркости. Номера фиксированы в `game_theme_token_map.json`: не перенумеровывать, новые оттенки добавлять в конец соответствующего семейства. Это compatibility ramp для прежнего оформления, а не повод добавлять произвольный новый цвет каждому компоненту.

Пример потребителя: `rgb(var(--tone-accent-024-rgb) / .18)`. RGB задаётся темой, а альфа остаётся интенсивностью конкретной рамки/тени. Такая запись является ссылкой на токен, а не прямым цветом. Для новых компонентов сначала использовать смысловые `--col-border`, `--col-accent`, `--col-text-primary`; compatibility shades нужны для точного переноса прежних вариаций.

Тема также владеет семью chrome texture parameters и цепочками tint filters для монохромных иконок. Adventure заменяет старый тёмный металл/кожу спокойными slate gradients, Classic сохраняет прежние URLs и фильтры. Растровые изображения предметов, сцен, карт, аватаров и маски иконок являются контентом и не перекрашиваются общей темой.

## Допустимые локальные значения

- Относительные размеры, grid/flex fractions, проценты, отрицательные координатные поправки, коэффициенты формул, clip polygons и аспект изображения — геометрия компонента, а не палитра.
- Размеры панелей и desktop breakpoint-условия остаются в shell CSS; обычный `var()` не подставляется в условия media queries.
- Геометрия теней, blur, transform, motion timing и opacity конкретных состояний остаются локальными, если они не являются общим параметром компонента. Их цвет берётся из темы.
- `transparent`, `currentColor`, `inherit`, `none`, `normal` и служебные значения браузера не требуют отдельного theme token.
- URL art и runtime-переменные `--city-service-stage-image`, `--game-action-icon-url`, `--game-menu-icon-url`, `--inventory-item-icon-url`, `--inventory-tooltip-icon-url`, `--nav-icon-url`, `--scenario-choice-icon-url`, `--service-icon-url`, `--service-marker-url` поступают из шаблонов/данных. `--rift-edge-col` и `--rift-edge-row` задают положение фрагмента сцены.
- World-generated art values могут описывать мир; рамки, заголовки и элементы управления используют пользовательскую game-палитру, а не `--world-accent`.

## Проверка и сопровождение

При добавлении theme-роли менять оба набора; их ключи должны совпадать. Проверять references, обязательные aliases, отсутствие циклов и прямых числовых цветов в собранном game CSS. Параметры `rgb(var(...))` разрешены. Не редактировать compiled outputs вручную.

`game_theme_token_map.json` фиксирует исходные оттенки, буквальные замены, декоративные параметры и SHA исходников до миграции. `tools/migrate_game_theme_tokens.py` — запрещающий повторный запуск первоначальный migration pass; последующие проверенные доработки отражены в текущих исходниках. Не использовать его как runtime-сборщик или автоматический рефакторер новых изменений.

Browser-проверки должны использовать runtime/preview загрузку обоих assets. Desktop scope: 3840×2160, 2560×1440, 1920×1080, 1366×768 и уменьшенная высота браузера. Classic проверяется изолированно; мобильная версия отложена. Статический контракт не заменяет визуальную проверку и не доказывает состояние production.
