# Доступ к backend API монстров

Реализовано в исходниках 2026-10-14. Это защита monster-части A07-03, а не закрытие всех административных API из этой находки. Деплой и изменения реальных данных не выполнялись.

## Разрешения

| Операция | Требование |
| --- | --- |
| GET `/api/admin/monsters/generated` | Служебный ключ чтения |
| GET `/api/admin/monsters/generated/summary` | Служебный ключ чтения |
| POST `/api/admin/monsters/generated/rebuild/plan` | Служебный ключ чтения; dry-run без применения |
| POST `/api/admin/monsters/generated/rebuild/apply` | Служебный ключ чтения и отдельный ключ изменения |

Служебный ключ передаётся в `X-Internal-Service-Key`, проверяется существующим механизмом backend и дополнительным запретом известных dev/default значений для каталога. Ключ применения передаётся в `X-Monster-Catalog-Write-Key`; сравнивается через constant-time comparison. Отсутствие, неверное значение, placeholder или совпадение с ключом чтения запрещают применение. Проверки стоят до создания сервисов и получения DB dependency.

Это разрешения служебного клиента/оператора, не новая система ролей игроков. Игровой JWT не заменяет эти ключи. Внутренние сервисные методы и локальные CLI не проходят HTTP-гейт и не изменялись в этой задаче.

## Настройка

Дополнение для готового каталога: `MONSTER_CATALOG_READ_KEY` позволяет отдельно настроить чтение монстров, сохранив общие ключи. Локальная Studio использует его для local source; на prod source локальный ключ не отправляется. Теперь этот read key настроен в локальном `.env`; ниже сохранено описание исходного состояния до подключения Studio. Применение не допускает совпадения write key с любым действующим read key.

- Backend: `FRONTEND_INTERNAL_SERVICE_KEY` либо существующий fallback `SITE_TO_GAME_SERVICE_KEY` должен содержать непубличный служебный ключ, отличный от dev/default значения.
- Клиент Studio: `BACKEND_INTERNAL_SERVICE_KEY` должен совпадать с ключом backend. Существующий клиент уже передаёт его в запросах; его код не менялся.
- Для ручного применения пересборки backend дополнительно получает `MONSTER_CATALOG_WRITE_KEY`, отличный от служебного ключа чтения. По умолчанию пустой, поэтому применение запрещено. Studio этот ключ не получает; записывающие маршруты Studio удалены предыдущим изменением.

Реальные `.env` и ключи в этой задаче не изменялись. Без вывода значений проверено: текущая локальная конфигурация использует dev/default ключ чтения, совпадающий у backend и клиента; отдельный ключ изменения не настроен. После обновления кода каталог в таком окружении вернёт 403, пока не настроен непубличный служебный ключ. Существующие общие ключи не ротировались, чтобы не менять доступ других клиентов молча.

## Проверки

52 локальных теста API монстров, Studio inspection и общей авторизации прошли. Проверены отказ до DB для отсутствующего/неверного ключа, запрет dev/default конфигурации, невозможность применения с правом чтения, запрет повторного использования read key как write key, успешные чтение/plan/apply при соответствующих credentials и чтение через настоящий клиент Studio с ASGI-подменой backend.

Ruff и diff whitespace прошли. Coverage для ограниченного прогона отключён; глобальная политика не менялась. Реальные БД, провайдеры и production не использовались.

Дальнейшие A02-06, A02-02 и A09-05 не исправлялись: профиль монстров нужно согласовать с новым каталогом, Combat/Rift требуют отдельного контракта, а оптимизация загрузки боя — предварительных измерений.
