# Начальный готовый Python-каталог монстров

Этап: новые контракты и базовое наполнение. Полное переключение спавна с сохранённых монстров на готовые определения ещё не выполнено.

Инспекция и раздел монстров Studio теперь переключены на этот набор через отдельные catalog GET endpoints; подробности — `docs/planning/tasks/studio_monster_catalog_inspection.md`. Старые записи БД не удалены.

## Источник и определения

`catalog/contracts.py` содержит неизменяемые FamilyDefinition, ClanDefinition, MemberDefinition и ImageAssetReference. Коллекции и вложенные механические данные заморожены, чтобы изменения экземпляра не могли испортить определения каталога.

Существующие Python-определения в `catalog/families/` остаются единственным редактируемым источником нынешних характеристик. `catalog/prepared.py` явно объявляет базовые кланы, а `catalog/authoring.py` преобразует определения в проверенные структуры. Это загрузка заранее заданного контента: окружение, случайная генерация, API и БД в ней не участвуют.

Начальный набор: 5 семей, 5 базовых кланов, 52 типа бойцов. Четыре обычные семьи — гоблины, бандиты, крысы и волки. Системная семья якорей зарегистрирована отдельно и исключена из обычного поиска, если потребитель явно не запросил системный контент.

Клан имеет постоянный ID вида `wolf_pack.base`; боец — `wolf_pack.base.alpha_prime`. Старый `variant_id` сохранён отдельно. Эти идентификаторы определяют каталог, а не живого противника: ID экземпляров при спавне предстоит отделить следующим этапом.

## Чтение

`catalog/registry.py` предоставляет `get_catalog`, `get_catalog_family`, `get_catalog_clan`, `get_catalog_member`. `catalog/indexes.py` хранит индексы в памяти и поддерживает поиск по семье, всем запрошенным тегам и допустимому уровню. Это фильтрация определений, не новая политика сборки встречи и не замена действующего habitat pool.

`catalog/validation.py` проверяет определения и связи до публикации индексов. Ошибки каталога должны останавливать загрузку, а не оставлять частично зарегистрированные семьи.

## Арты и тексты

`catalog/presentation.py` хранит Python-ссылки на существующие исходники изображений и их статусы. Во время загрузки JSON-манифесты не читаются. S3 не вызывается; asset_id предстоит связать с опубликованным объектом отдельно.

Для бойцов сохранено 46 ссылок на изображения. Два тематических волчьих изображения не назначены базовой семье; четыре системных бойца не имеют исходников в текущей коллекции. Статусы review_ready сохранены явно. Арт загонщика без соответствующего механического варианта не стал новым бойцом автоматически. Принятые имена из манифестов используются по существующим ID/алиасам; остальные названия пока остаются прежними variant IDs. Новая история кланов не придумывалась, описания семей/кланов пока требуют отдельного авторского наполнения.

## Совместимость и БД

Старые методы реестра возвращают свежие MonsterFamilyDTO/MonsterVariantDTO через переходный адаптер готовых определений. Его назначение — сохранить существующих потребителей и нынешние характеристики; он не является вторым источником контента.

Новый каталог загружается без создания кланов или бойцов в БД. Старые SQL/Mongo-записи не удаляются и не переписываются. При этом прежние materialization/repository и потребители сохранённых кланов ещё существуют: переключение игрового спавна, инспекции, тренировки, библиотеки и item narrative на новый каталог — следующий этап. Нельзя считать, что запись монстров отключена во всём приложении только из-за добавления нового каталога.

Формулы, оборудование, навыки, роли, уровни и версии нынешних семей сохраняются. Генерации других доменов и backend-права не меняются.

## Проверки 2026-10-14

Прошли 228 тестов монстров и 1094 теста Items/World/Combat/Rift, Ruff и проверка whitespace. Новые тесты проверяют неизменяемость вложенных данных, ID/ссылки, ошибочные механические поля, сохранность всех прежних определений, клан с неполным составом семьи и изолированную загрузку без DB/network/JSON-зависимостей.

После завершения отдельно сверены хеши всех пяти прежних механических DTO с состоянием до изменения: совпадают. Все 46 исходников изображений по новым ссылкам существуют. Обычный поиск возвращает только четыре базовых клана; системный требует явного включения. Реальные БД, провайдеры, S3 и deploy не использовались.

## Исправление состава по принятым артам

Базовая стая содержит 11 типов: тематические winter_maw/blood_howl исключены, добавлен pack_huntmaster (Вожак-загонщик); Фенрир сохраняет ID alpha_prime. Числовой профиль загонщика временно взят из прежнего winter_maw без изменения значений, тематические описание и теги заменены. Исходные legacy Python-ресурсы сохранены; БД не изменяется.
Крысиные элиты используют новые ID burrow_guard/ironfang/heavy_rat, нейтральные описания и теги; disease исключён из базового клана. У короля гоблинов убран трон из описания, у bandit_thug убрано происхождение от поселенцев.
Текущий каталог: 51 тип, 47 изображений; без артов только четыре системных владыки якорей.
