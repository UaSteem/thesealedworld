# Каталог снаряжения гоблинов

Данные находятся внутри семьи: `catalog/families/goblin_catalog/equipment/`. Это ссылки и готовые наборы, а не новая база механик предметов. Существующий предметный каталог остаётся владельцем base power, материала, аффиксов, текстов и расчёта предмета.

## Состав

- `entries.py`: 20 ссылок на существующие предметные основы; нож, броня, амулет и другие основы описаны один раз в этом списке.
- `sets.py`: 12 нынешних комбинаций слотов. Полные комплекты сейчас различаются; их не объединяли ценой замены снаряжения. Любое число бойцов может ссылаться на один и тот же набор.
- `__init__.py`: сборка семейного каталога.
- `catalog/equipment_contracts.py`: неизменяемые DTO ссылок, наборов и семейной коллекции, проверка ID/слотов через существующий ItemCatalogService.

Основа бойца использует equipment_set_id вместо скопированного inline loadout. Клан может назначить equipment_overrides по ID основы: значение — ID другого набора этой же семьи. Это полная явная замена набора, не цепочка частичных наследований.

Resolver выбирает набор клана или основы и возвращает прежний fixed_loadout. Метаданные equipment_set_id/equipment_source показывают происхождение: base_set или clan_override. API и Studio отображают итоговый набор; клиент не повторяет правила выбора.

Все12гоблинов сохранили характеристики, роли, навыки, доступность, вес появления, фактическое снаряжение, тексты и эффективный арт. Новая генерация предметов, тирные профили, случайность и новые аффиксы не добавлялись. Другие семьи пока сохраняют собственный inline loadout. Якоря не меняются. БД не используется и не изменяется; retired runtime остаётся отключённым.
