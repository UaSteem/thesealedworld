# Поиск и клиентский bootstrap каталога

Публичный вход — `src.backend.features.monsters.catalog` (ленивые экспорты через `__init__.py`). Для других доменов те же классы доступны через `monsters.public`. Реализация поиска — отдельный `catalog/search.py`, а не код внутри init.

```python
from src.backend.features.monsters.catalog import CatalogSearchService, MonsterSearchFilters

members = CatalogSearchService().search(MonsterSearchFilters(
    family_ids=("wolf_pack",),
    required_tags=("predator",),
    excluded_tags=("young",),
))
```

Фильтры: `family_ids`, `clan_ids`, `member_ids` (полные ID), `required_tags`, `excluded_tags`, `include_system`. Все категории соединяются AND, ID внутри одной категории — OR, все обязательные теги должны присутствовать; любой запрещённый тег исключает результат. Пустая коллекция не ограничивает поиск. Теги учитывают семью, клан и самого бойца. Неизвестный ID или несовместимые условия возвращают пустой tuple; одновременное требование и запрет одного тега — некорректный запрос.

Возвращаются неизменяемые MemberDefinition в порядке каталога. Поиск не делает случайный выбор, не собирает отряд, не создаёт экземпляр монстра и не обращается к БД. Якоря требуют явного `include_system=True`, даже при поиске по ID. Следующие параметры добавляются после разбора потребителей.

## Bootstrap

`MonsterCatalogBootstrapService().build()` возвращает отдельный типизированный DTO публичных метаданных: семьи, кланы, бойцы, связи ID, названия, описания, теги, роль, ID способностей и ссылки на арты. Характеристики и внутренние source_path не входят в этот ответ. Пустые авторские описания не заменяются придуманным текстом.

HTTP: `GET /api/admin/monsters/catalog/bootstrap`, под существующей защитой чтения. По умолчанию четыре обычные семьи/47 бойцов; `include_system=true` добавляет якоря. Это серверный маршрут: служебный ключ не передаётся браузеру; существующий игровой bootstrap и клиентский код автоматически не переключались.

Ответ: `schema_version`, `version`, `manifest.sections` с SHA256 для families/clans/members. Общая версия зависит от версии схемы и хешей содержимого. Хешируется передаваемая метаинформация, не бинарные файлы артов; при замене файла используйте новый asset/version URL.

ETag совпадает с версией. `If-None-Match` поддерживает обычный/weak ETag, список и `*`; ответ304 без тела. Cache-Control private,no-cache разрешает частное хранение с обязательной ревалидацией, а не публичное кеширование служебных ответов. Авторизация выполняется и для304. Фактическое хранение кеша на клиенте подключается отдельно.

## Локализованные тексты и дефолтные арты

Bootstrap теперь использует schema_version=2 и параметр locale, явный ru fallback и доступные языки; локаль включена в версию/ETag. Имена/описания разрешаются через text_id. Арт уже выбран из уникального варианта или дефолта основы, источник отражён в image_source. См. monster_texts_and_art.md.
