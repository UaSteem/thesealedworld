# Studio: инспекция готового Python-каталога

Реализовано в исходниках 2026-10-14. Раздел `/admin/content-ops/monster-browser` читает готовый Python-каталог, а не generated clan/member rows из БД.

## Путь чтения

Studio использует отдельный CatalogMonstersApi → GET `/api/admin/monsters/catalog` и GET `/api/admin/monsters/catalog/summary` → CatalogMonsterViewService → неизменяемые определения в памяти. Этот путь не имеет DB dependency и не создаёт/обновляет монстров.

Backend отдаёт отдельные DTO определений: постоянные ID, семью/клан, теги, обычный/системный статус, доступные уровни, базовые характеристики, навыки, фиксированное снаряжение и ссылки на арты. Это не рассчитанные участники боя: vitals, gear score, generated UUIDs и задачи генерации не подставляются как фиктивные поля.

Studio показывает 5 семей, 5 кланов, 52 типа бойцов и 6 бойцов без изображения. Есть фильтры семьи, роли, доступности на уровне и отсутствующего изображения. Клиент читает все страницы API, включая каталог больше 100 кланов. Карточки показывают статусы артов и учитывают зеркальное отображение. Записывающих действий нет.

## Изображения

46 связанных исходников скопированы byte-identically в `src/frontend/static/images/monsters/catalog/`. URL — `/static/images/monsters/catalog/<asset_id>.<extension>`. Studio использует существующий frontend static mount; исходная коллекция и её манифесты не выставляются целиком через HTTP.

Повторная публикация: `.\.venv\Scripts\python.exe tools/monsters/publish_catalog_images.py`. Скрипт берёт только ссылки готового каталога, проверяет source root и безопасные ID, не генерирует изображения, не обращается к БД/S3 и не удаляет файлы. Новые версии/замены ассетов публикуются отдельной операцией. S3 пока не используется для этого набора.

## Доступ

Добавлен `MONSTER_CATALOG_READ_KEY` — отдельный непубличный ключ чтения монстров. Backend принимает его в `X-Internal-Service-Key` для monster router, наряду с правильно настроенным существующим служебным ключом. В локальном `.env` ключ настроен без вывода значения и без ротации общих служебных ключей.

Studio автоматически использует этот ключ только для local source. Для выбранного prod source остаётся прежняя настройка служебного клиента; локальный ключ не передаётся на prod. Применение пересборки по-прежнему требует отдельного write key, который не может совпадать ни с одним допустимым read key. Общая авторизация других API не изменена.

Для обычного запуска требуется перезапуск backend и Studio после изменения кода/настроек. Production не обновлялся. Проверено без вывода секретов: local read key задан и совпадает у backend/Studio; write key не задан.

## Старые данные

Исторические generated endpoints, их сервис и сохранённые записи БД оставлены. Текущий раздел Studio их не вызывает; отдельный экран истории этим этапом не добавлялся. Игровой спавн ещё использует прежний путь — переключение инспекции не является переключением runtime.

Снимки прежних страниц/клиента сохранены в `archive/studio_catalog_inspection/2026-10-14/`.

## Проверки

242 теста монстров и Studio прошли; после визуальных правок прошли ещё 17 тестов страниц/интеграции/общей авторизации. Ruff прошёл. Реальный клиент Studio проверен против backend ASGI-приложения нового каталога с запрещённой DB dependency: вызывает только catalog GET endpoints; локальная картинка отдаётся с исходными байтами.

В браузере проверены каталог, состав гоблинского клана и карточка бойца с локальным изображением. Preview был изолированным локальным приложением с настоящими DTO/определениями и подменой transport, без реальных хранилищ, SSH-туннеля или production. Временный preview остановлен после проверки.
