# Monsters: структура по ответственности

Домен разделён на части по задаче. Внутри каждой части остаются только нужные ей технические слои; создавать пустой набор services/dto/integrations для каждой папки не требуется.

[Карта перенесённых модулей](../../../../docs/planning/tasks/monster_layout_mapping.json) связывает старые пути с новыми.

| Часть | Ответственность |
| --- | --- |
| `catalog/` | Определения семей и бойцов, загрузка/валидация реестра, существующая подготовка и хранение шаблонов |
| `encounters/` | Условия появления, habitat pools, выбор подходящего клана и состава группы |
| `instances/` | Итоговые данные конкретного бойца, оборудование и передача временных actor snapshots в Combat |
| `inspection/` | Представление каталога, характеристик и изображений для просмотра |
| `api/`, `events/`, `scripts/` | Внешние входы: HTTP, события и служебные команды |
| `dto/` | Временно общие внутренние контракты, которые пока описывают несколько частей сразу |
| `public.py` | Экспорты для существующих внешних потребителей домена |

Обычный путь: World/Rift задаёт условия → encounters выбирает контент каталога и состав → instances готовит участников → Combat ведёт бой. Инспекция читает данные, но не определяет спавн и боевые правила.

## Что изменено этим этапом

Расположение модулей и импорты организованы по ответственности. Это структурная подготовка: ID, формулы, выбор встреч, формат сохранённых данных и HTTP-контракты сохраняются. Архивы и исторические отчёты аудита сохраняют исходные пути. Активный API-заказ монстров не возвращается.

`public.py` пока не заменяет внутренние constructor graphs полноценным семантическим контрактом. Перенос файлов сам по себе не закрывает A02-02. Аналогично прежние калькуляторы в core не становятся собственностью Monsters лишь из-за новой папки: A02-06 остаётся следующей задачей. Нагрузка боевого ИИ A09-05 не меняется.

## Следующая логика каталога

Согласованное направление: полный вручную подготовленный Python-каталог семей, разновидностей/кланов и типов бойцов. Мир и рифты выбирают уже существующий контент по требованиям; новый вид или клан при спавне не придумывается. Изображения публикуются в S3, каталог содержит ссылки или стабильные ссылки на реестр ассетов.

После структурного переноса добавлен первый готовый Python-набор: новые контракты, 5 семей, 5 базовых кланов и 52 типа бойцов, загрузка и поиск без БД. В `catalog/materialization/` пока остаётся существующая программная подготовка сохраняемых шаблонов, а в `catalog/repositories/` и `catalog/integrations/` — их текущий путь SQL/Mongo. Следующий этап — переключение потребителей на готовый набор и архивирование прежнего пути записи. Старые записи БД сохраняются; переключение источника runtime ещё не выполнено.

Отдельно предстоит решить, какие параметры экземпляра можно менять при спавне, где принадлежат расчёты характеристик и каким контрактом другие домены запрашивают встречу. Шаблон каталога и живой экземпляр не должны разделять изменяемое состояние.

## Проверка переноса 2026-10-14

Перенесены 46 модулей, импорты и тесты обновлены. Прошли 217 тестов Monsters, 1111 тестов Combat/Rift/World/Items/Studio и 8 тестов AdminPlayers после последнего изменения внешних импортов. Ruff затронутых Python-файлов прошёл. Проверены новые пути в профильных инструкциях и ссылка на карту переноса.

ID семей/вариантов, роли, окна уровней и версии совпадают с сохранённой инвентаризацией. Ранее изменённые владельцем функции generation_fields сохранены после подстановки новых путей импортов. Реальные хранилища и deploy не использовались. Это подтверждение структурного этапа, а не завершение будущего каталога или исправление всех находок аудита.
