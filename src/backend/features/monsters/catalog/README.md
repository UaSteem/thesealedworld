# Каталог

Определения семей находятся в `families/`, новые неизменяемые контракты — в `contracts.py`, базовые кланы — в `prepared.py`, загрузка действующего реестра — в `registry.py`. Ресурсы характеристик и оборудования находятся в `resources/`, ссылки на существующие арты — в `presentation.py`.

`authoring.py` подготавливает проверенные определения из вручную заданных Python-данных, `validation.py` проверяет связи и механические данные, `indexes.py` предоставляет чтение и поиск в памяти. Новый набор содержит 5 семей, 5 базовых кланов и 52 типа бойцов. Он не читает манифесты JSON и не создаёт записи монстров в БД. Старые методы реестра адаптируют эти же определения для действующих потребителей.

Текущая подготовка сохраняемых шаблонов ещё находится в `materialization/`, `services/`, `repositories/` и `integrations/`. Это переходная реализация. Следующий этап — переключить подбор встреч и остальных потребителей на готовый каталог, затем убрать прежнюю запись шаблонов. Действующий спавн ещё не переключён этим этапом; старые данные БД сохранены.

Каталог определяет, какие монстры существуют. Выбор конкретной группы принадлежит encounters, а состояние отдельного противника — instances. Не добавлять заказ контента через API.

Волки переведены на вложенные контракты `nested_contracts.py`: общие основы в `families/wolf_catalog/bases/`, конкретные варианты в `families/wolf_catalog/clans/base/members/`. `resolve_family` раскрывает ссылки в прежние контракты чтения; основной источник волчьих данных — `wolf_catalog/family.py`, а не исторический `wolves.py`. Подробнее: `docs/planning/tasks/wolf_nested_catalog.md`.

Гоблины, крысы и бандиты также используют отдельные вложенные пакеты `goblin_catalog/`, `rat_catalog/`, `bandit_catalog/`. Якорные монстры оставлены в прежнем формате. См. `docs/planning/tasks/nested_starter_catalogs.md`.
