# Inventory Lab

При перетаскивании границы чата центральную область закрывает тематическая
заставка. Backing canvas не пересоздаётся на каждом движении; итоговый размер
применяется после отпускания. Закрытый инвентарь заставку не показывает.

Фильтры оформлены вкладками общей панели. Иконки переиспользуются по существующим
frontend URL из `ui/inventory-icons/` и `ui/inventory-gear/`; новые копии SVG не
создаются, attribution остаётся рядом с исходными наборами.

Отдельный экран инвентаря в общей Adventure-оболочке Game UI Lab.

```powershell
.\.venv\Scripts\python.exe -m game_ui_lab.inventory_app
```

URL: http://127.0.0.1:8880/ (`--port` для другого порта).
Текущий просмотр запущен на http://127.0.0.1:8881/ (`--port 8881`).
Персонаж/экипировка и чат остаются существующими HTML-компонентами. Центральный
рюкзак и всплывающая карточка нарисованы Phaser. Пояс из8 ячеек находится в HTML
под экипировкой, над тонкой полосой GS. Постоянной правой панели нет: сетка занимает
всю ширину, карточка появляется возле предмета и закрепляется щелчком.
Внешний размер инвентаря не зависит от предмета.
При недостатке высоты прокручивается содержимое карточки: колесо или ↑/↓ при
фокусе canvas. Наведение временное, нажатие закрепляет, Escape закрывает.

`data/inventory.json` — замороженный экспорт `inventory/future` (шесть реальных
мечей T0–T5, параметры и аффиксы). Экспорт сделан однократно; сервер не импортирует
backend/settings и не обращается к БД/API. В runtime нужны только stdlib и Jinja.
Строгая карта `/inventory-art/<known visual>/image|thumbnail` обслуживает уже
собранные WebP из `assets/item_art/renders`, без копий во frontend. Исходные
production URL сохранены в данных; S3 и его политики не меняются.

Модули data/theme/scene/boot разделены для будущей интеграции. Theme adapter
читает семантические CSS-токены Adventure; отдельной палитры Phaser нет.
Scale.NONE и ResizeObserver явно изменяют canvas при движении границы чата.
Изменения снаряжения, оценка, вес, перенос предметов и игровая сеть отсутствуют.
Desktop scope: 1366×768–2560×1440; принятие визуала отдельно от production.

Для проверки точного размера viewport в iframe:
`/ui-static/game/scenes/inventory/viewport-check.html?w=1366&h=768`.
Масштабируется только показ проверочного iframe; внутри Phaser получает настоящий
viewport указанного размера. Это вспомогательная страница проверки, не экран игры.

Пояс расположен сверху и остаётся неподвижным. Рюкзак прокручивается колесом
независимо от карточки; число строк вычисляется по `grid_w/grid_h`, без лимита40.
Размер ячейки48–64px зависит от ширины, не высоты сцены. Карточка сохраняет свой
viewport. Для демонстрации длинного списка: `http://127.0.0.1:8881/?copies=12`
(72 локальных mock-экземпляра тех же6 мечей, уникальныеID; без изменения JSON).
`copies` допускает1–100; это ограничение генератора демонстрации, не ёмкость игры.

Текст Phaser использует `Text.setResolution(max(2, devicePixelRatio))`, integer
positions и roundPixels; CSS canvas не растягивается. В Phaser3.60 vendor API
Text.setResolution подтверждён по исходнику. Global renderer resolution не
добавлен: backing/CSS размеры уже совпадают; причина исходного размытия не
установлена измерениями. Чёткость и колесо проверяются в браузере отдельно.

Категории используют существующий ItemType: «Все», «Оружие», «Броня» (также
одежда), «Аксессуары», «Расходники», «Ресурсы» (также материалы), «Квестовые».
В frozen слепке только мечи; остальные вкладки показывают пустое состояние.
Редкость не превращает предмет в отдельную категорию.

Нижняя полоса показывает **MOCK-вес**: 2кг на каждый меч +4кг надетого, шкала30кг.
Это фиксированные числа интерфейсного макета, не вес/лимит игрового DTO. Вес не
зависит от активного фильтра. «Разборка» и «Крафт» открывают закрываемое локальное
уведомление. Закреплённая карточка имеет кнопку «Заменить» при занятой основной
руке (иначе «Надеть»); её нажатие также показывает уведомление стенда. Ни одна
кнопка не удаляет/изготавливает/надевает предметы и не вызывает игровой API.
