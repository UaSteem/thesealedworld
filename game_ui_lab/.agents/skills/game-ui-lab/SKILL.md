# Game UI Lab

Работай с существующей лабораторией. Точка входа — `app.py` → `templates/index.html` → `static/game/core/boot.js`. Не создавай новый сайт, второй Game/canvas, альтернативную оболочку или страницу-замену, если это прямо не поручено. Новый компонент допустим как часть порученной правки, с подключением в существующий интерфейс.

## Перед правкой

1. Прочитай [текущие решения](../../../docs/current-decisions.md). Различай принятое, временную примерку, варианты и известные дефекты.
2. По [карте файлов](../../../STRUCTURE.md) найди компонент и прочитай его код. До изменения назови пользователю экран, файлы и границы правки одной короткой фразой.
3. Выполняй конкретное поручение. Обсуждение варианта не разрешает реализацию. Не меняй соседние страницы, навигацию или оформление «заодно». Если потерял контекст, перечитай задание и решения, не восстанавливай их догадками.

## Границы

### Владелец логики и роль лаборатории

Lab — самостоятельный прототип будущего фронтенда игры. Он не обязан повторять текущий интерфейс, компоненты или клиентскую архитектуру `src`. Собственные сцены, контроллеры интерфейса, камера, анимации, навигация и раскладка здесь допустимы. Готовый прототип переносится в основной фронтенд отдельным поручением.

- В Lab не должно быть backend-кода: импортов внутренних backend-сервисов, копий генераторов, resolver, расчётов урона/прогрессии и правил разрешения игровых действий. Готовая backend-логика принадлежит `src`, а не лаборатории.
- Lab показывает данные и имитирует получение ответов backend через fixtures/mock-адаптер. Допустим выбор заранее подготовленного следующего ответа; нельзя ради демонстрации заново реализовывать backend-алгоритм.
- При существующем API ориентируйся на его контракт. Если API ещё не готов или новый UI требует иной модели, явно пометь предварительный формат и отличия; не выдавай его за проверенный backend-контракт. Текущий формат src не запрещает новый дизайн интерфейса.
- Повторное использование фронтенд-кода src возможно по необходимости, но не обязательно. Сам факт отдельного Lab-клиента не является дефектом. См. [проверку текущего состояния](../../../docs/frontend-boundary-check.md).

- Рабочая область — `game_ui_lab`. Основной `src`, `rift_lab`, каталоги игры, серверы и данные игры не менять без отдельного поручения. Имеющиеся зависимости на чтение перечислены в карте файлов.
- Сохраняй цепочки игровых переходов и возвратов. Debug-кнопки дают прямой доступ при разработке, а не заменяют эти цепочки. Проверяй ограничения боя.
- Исправляй причину в её владельце. Если требуется обход (например, скрыть дефект картинки отдельным объектом в коде), сначала сообщи причину, конкретные варианты и последствия и обсуди выбор. Наличие старого обхода не означает его одобрение; обычное исправление источника и уже согласованное решение не требуют повторного разрешения.
- Mock — локальный слепок для дизайна, не игровая механика. Сверяй состав/названия с каталогом. Если нужен полный перечень, не заменяй его небольшой выборкой. Недостающие данные обозначай явно; модификаторы не равны бафам.
- Новый арт и варианты готовь в `experiments/visuals/<задача>/`. В `static/game/assets/` помещай только выбранное и подключённое. Мастера — `sources/`, заменённое — `experiments/history/`. Не оставляй ненужные оригиналы в active assets и не создавай второй источник истины.
- Для передачи через Git проверь доступность всех зависимостей из чистого checkout. Не добавляй ссылки на игнорируемые локальные папки и абсолютные пути компьютера. Сам коммит или изменение Git-границ требуют соответствующего поручения.

## Проверка и завершение

Запуск и команды — в [README](../../../README.md). Пользуйся существующим запуском; не переписывай сервер ради изменения внешнего вида.

Открой именно изменённый экран в актуальной вкладке, дождись фактической отрисовки. Проверь перекрытия, читаемость, ввод/клик, закрытие/возврат и ближайший связанный переход. Для оболочки проверь 1366×768 и 1920×1080, а на более широком окне — сохранение предела1920. Клавиатура/resize/скролл проверяются по затронутому поведению. Структурные тесты не доказывают визуальное соответствие. Если браузерная проверка недоступна, так и сообщи.

Короткий итог: что изменено; что реально проверено; оставшиеся пробелы/обходы. Не объявляй внешний вид принятым за владельца. Обновляй current-decisions только после явного решения владельца; текущий код сам по себе не является таким решением. Независимый ревизор — только по выбранному режиму задачи.

Журнал боя может использовать общую оболочку вкладок с чатом, но его источник данных, обновления и renderer принадлежат боевому представлению. Не проводить события боя через чат-сервис, отправку или хранилище. Текущий Lab mock описан в current-decisions.
