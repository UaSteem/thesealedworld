# Границы нового игрового клиента

## Общая оболочка и игровые сцены

В `static/game/shell` находятся статус, чат и размеры внешней HTML-оболочки.
В `templates/shared` — общая разметка. Бой и инвентарь больше не поддерживают
собственные копии этих элементов. Локальные сцены не меняют разметку всей страницы.

`core/boot.js` создаёт один Phaser.Game после загрузки каталога. Классы сцен
регистрируются в `GameClientScenes`; сейчас основной клиент запускает `combat`.
`data-game-scene` выбирает только зарегистрированный ключ, не имя JS-файла.

Боевой `scene.js` отвечает за собственное поле и демо-представление. Командная
панель и инспектор вынесены в `ui/`. Геометрия находится в `shared/`.
Нынешние глобальные имена `LabControlZoneV2`, `LabTargetInspector`, `HexCardLayout`
сохранены внутри Lab для ограниченного структурного шага. Это ещё не окончательный
публичный API будущего production-клиента.

Инвентарь находится в `scenes/inventory`. Его `client.js` адаптирует существующую
scene factory к логическим размерам и DPR общего Game, не создавая второй канвас
и не меняя статус/чат. Core лениво импортирует модуль при первом открытии.
Переходы используют sleep/wake: состояние боя и инвентаря сохраняется.
Отдельный `boot.js` и сервер8880 оставлены для проверки той же factory.
Рифт пока остаётся отдельным стендом.

Общий resize coordinator находится в `shared/resize.js`: при перетаскивании
границы чата в инвентаре backing canvas сохраняется до отпускания указателя.
После отпускания применяется последний размер, с временным тематическим overlay.

## Ассеты

`assets/catalog.json` содержит группы `combat-core`, `combat-controls`,
`combat-inspector`, стабильные ключи, URL, размеры и SHA-256 исходных PNG.
UI-модули запрашивают группу, а не держат пути к планшеткам внутри себя.
Координаты кадров остаются у их компонентов до отдельного этапа упаковки.

`core/assets.js` не загружает повторно текстуру, которая уже находится в
Texture Manager. SVG текущего прототипа и общие картинки статуса ещё используют
существующие frontend URL. Новый каталог не притворяется универсальным загрузчиком
всех игровых ресурсов. Фон остаётся CSS/DOM-слоем оболочки боевой сцены.

Lab по-прежнему использует `Cache-Control: no-store` для удобства разработки.
Production-кеширование с hash-URL, выгрузка по бюджету и подготовка уменьшенных
текстур описаны отдельно в плане ассетов; они не внедрены этим переносом.

## Демонстрационные данные и API

Модель очереди и численные параметры боя пока находятся в боевой сцене.
Перед runtime-интеграцией нужно выделить presentation state/adapter,
сопоставляющий реальные снимки цели, очередь и события размена.
Демо не является источником формул, правил выбора противника или контрактом API.
В шаблоны и Phaser не добавлять прямой доступ к БД/Redis.

## Будущий перенос в src

Это целевое соответствие слоёв, **не выполненная миграция**:

| Lab | Будущий владелец в frontend |
| --- | --- |
| `templates/shared` | общие game templates и session shell |
| `static/game/core`, `shared`, `ui`, `scenes` | клиентские JS-модули игры в frontend static |
| `static/game/shell/*.css` | общий игровой CSS с существующими theme tokens |
| `static/game/assets` | frontend-owned runtime images/atlases + manifest |
| `data`, демо-модель в scene | заменяются view models и typed Backend API adapter |
| `app.py`, `inventory_app.py` | не переносить в runtime как новые серверы |

Точные target-пути согласовать с существующими `src/frontend/game_features/session`,
`game_features/combat`, `integrations/backend_api`, `templates/game` и CSS-сборкой.
Не создавать второй сайт/SPA или независимую авторизацию. Реальные переходы
между доменами остаются под управлением существующей frontend-сессии.

## Проверка

1. Contract tests проверяют порядок core→scene→boot, общие shell-модули и каталог.
2. Браузер проверяет четыре desktop размера, осмотр/атаки/сворачивание/resize.
3. Повторный вход в Scene проверяется отдельно: инспектор присутствует после re-entry.
4. Inventory Lab проверяется после перемещения модулей и shared templates.
5. Инвентаризацию пересобирает `python -m game_ui_lab.tools.audit_assets` из
   актуальных browser observations; это не проверка качества downscale.
