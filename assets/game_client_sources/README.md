# Общие исходники графики игрового клиента

Эта папка сохраняет нужные исходники независимо от локальных `game_ui_lab/` и `rift_lab/`. Лаборатории не нужны для проверки и сборки текущих runtime-копий.

- `combat/ui/`: два PNG-мастера для 11 точных обрезок интерфейса. Имена мастеров и исходные байты сохранены.
- `places/originals/`: пять исходных JPEG 4096×2284, полученных от владельца, и побайтная копия их `source-manifest.json`. Это редактируемые художественные мастера, а не файлы для загрузки игроком.
- `places/painted/`: четыре уже сжатых WEBP, которые копируются в runtime без перекодирования.
- `manifest.json`: SHA-256 и размеры всех 12 исходных файлов. `origin_local_path` — запись происхождения, а не путь для чтения сборкой.

`residential-quarter.jpg` сохранён как художественный мастер. У него нет текущей runtime-копии: эта задача не добавляет новый экран или фон в игру.

## Подготовка сжатых фонов

`tools.game_ui_migration.build_place_backgrounds` читает пять JPEG из `places/originals/` и пишет пять WEBP в `places/painted/`, вместе с manifest параметров сжатия. Это явная пересборка общих исходников, а не публикация runtime. Она может создать `residential-quarter.webp` в общей папке, но `build_runtime_places` публикует только четыре выбранных фона; жилой квартал в игру не добавляется автоматически.

При намеренном изменении исходников или повторном сжатии следует также пересмотреть общий `manifest.json` и проверить изменившиеся хеши. В текущем снимке сохранены прежние четыре WEBP без повторного сжатия; подготовка JPEG не запускалась.

## Сборка runtime-копий

```powershell
.venv/Scripts/python.exe -m tools.game_ui_migration.build_ui_assets
.venv/Scripts/python.exe -m tools.game_ui_migration.build_runtime_places
```

Первая команда пересобирает crops и каталог в `src/frontend/static/images/game-client/`. Вторая копирует утверждённые WEBP и пишет manifest в подпапке `places/`. Команды локальные, без генеративного ИИ и публикации в S3. Собственного режима `--check` у них нет.

Для проверки без перезаписи runtime-файлов:

```powershell
.venv/Scripts/python.exe -m pytest tests/frontend/test_game_client_assets.py --no-cov -q
```

Тесты проверяют исходные хеши, совпадение runtime-обрезок с PNG-мастерами и WEBP с утверждёнными копиями. Проверка сборщиков перехватывает записи в памяти и запрещает чтение Lab-путей.

Существующие runtime-файлы остаются в `src/frontend/static/` и копируются Docker-сборкой из этой папки. Большие мастера в runtime-контейнер не копируются.
