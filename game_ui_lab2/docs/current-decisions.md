# Текущие решения игрового клиента Lab2

## Область и стек

- Активная разработка нового игрового клиента идёт в game_ui_lab2: Vue3 + JavaScript, Vite, Phaser3. TypeScript и Python в клиент не добавлять. UI не обязан повторять старый production frontend.
- game_ui_lab2/src — исходники нового клиента, их править можно. Корневой ../src — основное приложение, его сейчас не меняем. game_ui_lab — предыдущий работающий образец; rift_lab — отдельный прототип рифта, не runtime-зависимость клиента.
- Новую Lab2 пока не переименовываем, старую не удаляем. После приёмки заменить старую Lab; позднее перенести готовый клиент в корневой src/game_client и убрать заменённую игровую часть src/frontend с проверкой зависимостей. Это не разрешает делать перенос сейчас.

## Сохраняемая композиция

- Один Phaser Game/canvas, игровая область максимум1920px по ширине. Vue управляет оболочкой, HUD/меню, персонажем, инвентарём, квестами, сообщениями и окнами мест; Phaser — полем/камерой/анимациями.
- Принята компоновка PR4: портрет и экипировка4×4.5. Не делать новый дизайн при технической правке. Вкладки персонажа: Снаряжение, Характеристики, Билды. В Характеристиках нет боковой экипировки. Билды не реализованы и под вопросом.
- Квесты — отдельная страница, узкий список/статус и широкое описание справа. Диалоги квестов в fixture отсутствуют. Состав настроек не определён.
- Debug — технический верхний заголовок с кнопками всех страниц. Он не заменяет игровые цепочки и возвраты. В бою управление персонажем/инвентарём/квестами/настройками недоступно. Новая компоновка боя обсуждается отдельной задачей; поле и панели самовольно не переделывать.
- Навыки:9 групп,41 навык,3 открыты в mock. Группы раскрываются, недоступные видны с замком; checkbox Скрыть недоступные убирает закрытые навыки и пустые группы, общий счётчик3/41 сохраняется.
- Сообщения: нижние соединённые вкладки Мир/Локация/Группа/Торговля/Система, прозрачная история с градиентом без наведения. Географический охват Локации/Торговли и фильтрация каналов по страницам ещё не закреплены.
- Бой в том же блоке — отдельный журнал только в combat, без поля ввода. Отдельные gateway/подписки/данные; не использовать чат-сервис, отправку и хранилище. Mock log не синхронизирован с HP на карточках и не является расчётом боя.
- Рифт: фиксированное поле для примерки, зум1.00 по умолчанию и как предел отдаления, Debug-галочка снимает ограничение. Активные текстуры1024, ель512; дальнейшее снижение до512 не выполнено. Реального перемещения/генерации нет. Спорный infill елью унаследован и не считается одобренным новым решением.

## Данные и граница backend

Компоненты отображают входные данные и отправляют намерения через сценарий/gateway. Mock adapter возвращает заранее подготовленный ответ/состояние; никаких копий backend-алгоритмов, Python-сервисов, генераторов, resolver или БД. Сверяться с возможностями backend сейчас, способ сборки запросов проектировать при интеграции. Недостающие API/данные отмечать явно. У боёв соло/группы планируется общий WebSocket-транспорт; он ещё не реализован. Tauri отложен.

## Модификаторы: поправка владельца, не повторять ошибку

145 полей FullModifiersDTO — технический перечень общей схемы, не145 модификаторов игрока. Выгрузка удалена из UI. Состав панели задаёт явная презентационная карта src/mocks/player-modifier-layout.json, сверенная с потребителями боя и контрактами аффиксов; покрытие DTO не является целью интерфейса.

- item_* — параметры боевых предметов, не постоянные модификаторы персонажа. Не путать с бонусами надетой экипировки, которые входят в характеристики игрока.
- Внутренние raw/effective/mastery поля, служебные caps и косвенные расчётные коэффициенты не показывать самостоятельными пользовательскими модификаторами. Не добавлять поле только потому, что оно есть в DTO.
- В Атаке показывать профили основной/второй руки только для имеющегося оружия: итоговый урон, точность, критический удар. Общие прямые бонусы атаки показывать отдельно. Щит не создаёт вторую атаку; блокирование и защита щитом находятся в Защите и появляются только при щите.
- Итоги атак приходят готовыми в modifier_context.attacks из mock gateway; это демонстрационные ответы, не вычисление в браузере и не подтверждённый production API. Добавление оружия требует соответствующего готового профиля в ответе.
- Панель разделена на Боевые и Мирные. Мирные параметры разрешено оставить; текущий набор групп — рабочий прототип, а не утверждение о готовности всех мирных механик.
- Для выбора отображения проверять реальные потребители боя и комментарии об отключённых механиках, а не только схему/поиск имён. Сопротивления могут не влиять на снижение урона, но участвовать в наложении состояний. Бафы/дебафы — отдельные сущности.
- Известны расхождения витрины с resolver: physical_damage_bonus в текущем raw_roll прибавляется как число, не процент; интервалы и итоговая точность также требуют сверки. Не копировать формулы в браузер для обхода: будущая серверная проекция должна отдавать корректные значения/value_text.
- Неподтверждённые/временно отключённые боевые механики не добавлять в видимый список без уточнения. Бафы и боевые предметы не включать в постоянные модификаторы игрока.

## Концепции, не готовые механики

Диалоги/город/добыча/итог боя пока содержат намерения и варианты из src/mocks/page-briefs.json. Пробуждение — отдельное начало игры, не квест; обычные диалоги предполагаются окнами, на мобильном возможен весь экран. Смерть/победа могут быть итоговой страницей или интерактивной панелью. Добыча — страница или окно/сумка. Город — старый набросок, новая концепция не утверждена. Не превращать текст вариантов в выбранный дизайн без поручения.
