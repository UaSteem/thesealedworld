# Анализ первопричин

Для каждой находки начни с audit ID и исходного evidence. Найди текущую точку входа, фактический путь исполнения, зависимости и уже действующие защиты; проверь соответствующие тесты и конфигурацию. Сопоставь поведение с актуальным контрактом профильного skill, источниками в `src/` и утверждёнными решениями. Если контракт спорный или ещё не утверждён, не объявляй выбранную архитектуру ошибочной по одному черновому плану.

Запиши: нарушенный инвариант; минимальные условия проявления; первопричину на уровне владеющего слоя; другие проявления; контрпример или защиту; остаточную неопределённость. Для backend проверь feature/integration/infrastructure и границы HTTP/API; для persistence — источник истины и владельца key space; для combat, content, rift, studio и frontend — соответствующий domain skill. Не переноси правило из одной области в другую без проверки её контракта.

Повторно инвентаризуй доступные отчёты перед сравнением: утверждение старого аудита об отсутствии другого отчёта может устареть. Сравни ID внутри отчёта и между отчётами. Помечай как дубликаты только случаи с одной причиной, одним исправлением и совместимой проверкой результата. Если причина общая, но нужны независимые исправления, сделай общую родительскую задачу и отдельные зависимые участки. Если проявления похожи лишь названием домена или симптомом, оставь их раздельными. Сохраняй все исходные ID и конкретные пути, чтобы ни одна находка не потерялась при объединении.

Если путь или код после аудита изменился, проведи повторную проверку; при нехватке доказательств оставь гипотезу и укажи безопасный способ её подтвердить. Не подменяй исследование исправлением.
