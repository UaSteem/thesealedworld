# Шаблон проекта плана

При запросе письменного плана для одного аудита используй `audit/plans/XX_remediation_plan.md`, где `XX` — номер исходного отчёта. Для отдельной находки используй её ID в имени плана; при нескольких отчётах выбери ясное имя по охвату и перечисли все источники. Создавай файл только если пользователь запросил отчёт или план. План не является разрешением на реализацию, а открытые решения остаются за владельцем.

Сохраняй эти разделы в указанном порядке, сокращая содержание по масштабу запроса:

1. **Цель и исходный аудит** — охват, audit ID, дата/версия источников.
2. **Актуальность исходных доказательств** — что перепроверено в текущем коде, что изменилось, что неизвестно.
3. **Сводка severity и стадий** — четыре независимые оси для каждой находки: severity, доказательность, стадия, срочность.
4. **Подтверждённые первопричины** — инварианты, текущий execution path, защищающие механизмы.
5. **Дубликаты и пересечения** — соответствие всех исходных ID группам причин, включая другие аудиты.
6. **Предлагаемые варианты исправления** — локальный и оправданный системный варианты, плюсы/минусы.
7. **Риски и зависимости** — соседние домены, миграции, release/wipe последствия, стоимость.
8. **Regression/integration tests** — наблюдаемый контракт и нужная граница проверки.
9. **Предлагаемые обновления project skills** — Knowledge и Workflow, источник повторяемого пробела.
10. **Предлагаемые изменения CI/validators** — Enforcement, ожидаемый сигнал и ограничения.
11. **Варианты порядка выполнения** — независимые и последовательные задачи, альтернативы при выборе.
12. **Вопросы, требующие решения владельца** — только неразрешённые существенные решения.
13. **Открытые ограничения** — недоступный код, данные, среда, невоспроизведённые гипотезы.

У каждой предлагаемой задачи должны быть исходный audit finding ID и конкретный участок актуального кода (путь и, когда надёжно известно, строки). Для удалённой или изменённой реализации укажи исходный путь и результат повторной проверки вместо выдуманной текущей строки. Ссылки делай относительными к файлу плана. Не переноси большие фрагменты аудита в новый файл. Отличай исполненные проверки от предложенных.
