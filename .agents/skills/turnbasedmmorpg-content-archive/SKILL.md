# Локальный архив игрового контента

Постоянная точка входа: `archive/data_retirement/README.md`, реестр снимков: `archive/data_retirement/INDEX.md`. Данные находятся в `archive/data_retirement/snapshots/`; они локальные, не запакованы и исключены из Git. Не искать их в memories или архивных копиях исходников.

## Поиск и чтение

1. Прочитать INDEX.md, затем manifest.json нужного снимка.
2. Различать полноту копии и удаление из источника: статус сохранённой копии не подтверждает вывод данных из игры.
3. PostgreSQL JSONL сопровождается описанием типов/ключей; Mongo — canonical Extended JSON. Читать штатным BSON-декодером, не терять UUID/Decimal/Date/ObjectId.
4. Перед использованием проверить сохранённые SHA256 и количества строк. Не исправлять готовый снимок на месте.

## Новый экспорт

Для старых монстров инструмент `tools/monsters/export_legacy_catalog.py`; сначала прочитать его CLI и убедиться в целевом локальном источнике. Выгрузка ограничена generated_clans, generated_clan_members, monster_habitat_clan_pool_entries и связанными generated_monster_actors. Никакие AI-задачи, аккаунты, инвентарь, рифты и другие коллекции автоматически не включаются.

Создавать уникальный каталог снимка. Сохранять manifest с форматами, количеством, SHA256, границами источника и зависимостями. assets-manifest содержит ссылки; без отдельного копирования бинарные арты не сохранены этим экспортом. В индекс добавлять только завершённую проверенную копию. Не печатать DSN или ключи.

## Удаление и восстановление

Экспорт сам не удаляет записи. Перед отдельным удалением проверить архив, активных потребителей и внешние зависимости. Если энкаунтеры читают старые сохранённые кланы, копировать допустимо, а удаление до переключения ломает встречи. Старые записи не смешивать с вручную подготовленным Python-каталогом. Не делать CASCADE по зависимым системам без явно определённого состава операции.

Восстановление требует отдельной реализации с проверкой типов и связей; наличие JSONL не означает, что автоматический restore уже реализован. Для рифтов и другого контента границы выгрузки определяются отдельной задачей.

## Выполненная monster-alpha операция

Снимок старых монстров — `2026-10-15-legacy-monsters-01`; актуальный статус смотрите в INDEX.md и `cleanup-receipts/`. В ветке monster-alpha старый runtime отключён постоянным guard. Проверенный локальный снимок очищен из рабочей БД; не считать пустую базу потерей архива.

Инструмент `tools/monsters/retire_legacy_catalog.py` по умолчанию делает dry-run, проверяет локальный источник и полное совпадение с архивом; применение требует `--apply --confirm-local`. Удаляет только архивированные ID, создаёт отдельную квитанцию. Повторное применение к уже очищенному источнику откажет из-за несовпадения — это не причина обходить проверку. Квитанции локальные и исключены из Git.
